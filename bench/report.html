Como ler estes números

O que foi mantido igual nos dois lados
  • Mesmo contrato HTTP, mesmas regras de validação, idempotência, retry e rate limit.
  • Mesmo gerador de carga (cmd/loadgen) e mesmo provedor simulado (cmd/provider).
  • Mesma máquina, mesmo payload, mesma duração, mesma concorrência, mesmo aquecimento.
  • Python usa asyncio + aiohttp, não código síncrono — comparar Python bloqueante com Go concorrente não seria comparação.
Limitações — leia antes de concluir qualquer coisa
  • Uma execução isolada não é resultado. Rode várias vezes e observe a variação antes de afirmar algo.
  • Windows + OneDrive + antivírus introduzem ruído. Um servidor Linux ocioso dá números bem mais estáveis.
  • Este cenário é I/O-bound: o trabalho real é esperar a rede. É onde o Python assíncrono compete melhor. Cenários CPU-bound teriam outro desfecho.
  • Python roda em um único processo. Em produção usaria-se múltiplos workers (um por núcleo), o que muda a foto de vazão — mas também a de memória.
  • O gargalo pode ser o gerador de carga ou o provedor simulado, não o servidor. Se os dois lados baterem no mesmo teto, é sinal disso.
